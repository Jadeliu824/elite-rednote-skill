# Stage 3 — Editorial Strategy

Before writing, define *what this post actually is*. This stage decides whether a topic becomes content; it is not a formality.

## 1. Define the brief

Answer all six, in this order:

1. **Target reader.** Who exactly is this for? A founder, an operator, an investor-curious reader? What do they already know? What do they worry about?
2. **Core question.** The single question the post answers. If there is no question, there is no post — only a summary.
3. **Central argument.** The answer to that question, stated as a claim someone could disagree with.
4. **Editorial angle.** The frame that makes the argument *this* post and not another one. The 局内人 perspective, the "如果是我会怎么做", the "普遍解读漏掉了关键".
5. **Reader takeaway.** What the reader can carry away and use — one sentence.
6. **Why now / why ELITE.** Why this deserves attention now, and why ELITE is the one to publish it (access + judgment).

## 2. Run the angle tests

From `references/editorial-guidelines.md` §5.1:

- **So what** — does it deserve attention now, from this reader?
- **Tension** — is there something to argue with?
- **Originality** — would a summary of the same source produce the same post?
- **Judgment** — is there a place for the creator's own view?

If any test fails, the topic is rejected here — it is not rescued in writing. Return to Stage 1 with a sharper candidate.

## 3. Determine the Product Bridge

Check `references/product-inventory.md` for a real, matching product. Answer (per `references/commercial-strategy.md` §4): content role, pillar, whether the knowledge base contains related content, what the reader wants next, what systematic value the paid tier offers, and the CTA. If no verified product matches, record "无直接产品关联" and do no product CTA.

## 4. Record

Fill `templates/editorial-brief.md`. The brief's central argument becomes the spine of the writing and the headline. If the writing stage cannot stay true to this brief, the brief is wrong and must be revised — not silently abandoned.
